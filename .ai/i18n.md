# Copy, locales & errors

Six catalogs, English is the single source of truth. `scripts/i18n-check.mjs` (`pnpm i18n`) verifies the
mechanical parts, `tsc` verifies the rest.

## Files

| File | Role |
|---|---|
| `src/i18n/messages/en.ts` | source of truth: `MessageKey = keyof typeof en` |
| `src/i18n/messages/zh-CN.ts`, `zh-TW.ts`, `ja.ts`, `ko.ts`, `es.ts` | typed as `Messages` = complete `Record<MessageKey, string>` |
| `src/i18n/types.ts` | `Locale`, `LOCALES`, `LOCALE_LABELS`, `DEFAULT_LOCALE` |
| `src/i18n/index.ts` | `t()`, `tp()` (plurals), `hasMessage()`, `currentLocale()`, `applyLocale()`, `onLocaleChange()`, `useT()` / `useLocale()` hooks |
| `src/i18n/format.ts` | `Intl` formatting that needs the active locale: `formatNumber()`, `relativeTime()` |
| `src-tauri/src/i18n.rs` | the few native strings (Dock menu, tray) — Rust draws those, not the webview |

Adding a language: new `messages/<locale>.ts`, add the id to `LOCALES`, add its endonym to
`LOCALE_LABELS`, and make sure `src-tauri/src/i18n.rs` maps the tag.

## Rules

- **UI copy only through `t()`.** A CJK literal in a `.ts`/`.tsx` string fails `pnpm i18n:scan`. Chinese
  *comments* are fine (and are house style in older files).
- **Placeholders** are `{name}` and must exist in every locale for that key, with the same names. The
  scan also catches the reverse (a locale inventing `{path}` that English does not have).
- **Plurals** are `'one form | other form'`, rendered with `tp(key, count)`. `zh-CN`, `zh-TW`, `ja`, `ko`
  have exactly one form; `es` follows English (`1 | 2`).
- **Interpolation is by name**, not position, so word order can change per language.
- **Locale switching is live**: `applyLocale()` sets `<html lang>`, notifies non-React subscribers, and
  pushes a `localeEffect` into every editor view (`src/editor/locale.ts`), because conflict buttons,
  inline blame and fold arrows are DOM built by extensions that do not re-render with React.
- **A new shared setting must be in `SHARED_KEYS`** in `src/store/settings.ts` — `locale` is, so every
  window switches together.

## Error codes

Rust never sends a translated sentence for a user-visible failure:

```rust
AppError::c("io.notFound")                  // code only
AppError::p("io.other", [("error", text)])  // code + params
AppError::new(tool_output)                  // raw text, shown as-is (git / formatter output)
```

- The frontend renders `error.<code>`; params must match the `{name}` placeholders in the catalogs.
- `src-tauri/src/error.rs` maps `std::io::ErrorKind` to `io.notFound` / `io.permissionDenied` /
  `io.other` — those three strings are parsed by `scripts/i18n-check.mjs`, so renaming one there means
  renaming the key in the catalogs.
- `error.message` is the raw-text bucket (`AppError::new`), never translated.
- Every other `error.<code>` in the catalogs must correspond to a code Rust actually emits, or the
  script reports "text has no matching backend error".

## Adding copy

1. Add the key to `src/i18n/messages/en.ts` in the right section (the file is grouped by area).
2. Add the same key to the other five catalogs; 1 plural form for zh-CN / zh-TW / ja / ko.
3. Use it through `t('key')` (or `t('key', { path })`).
4. Leave execution to the user-triggered [verification gate](./skills/verify/SKILL.md) or CI. Its
   `pnpm i18n` step lists unreferenced keys as notes and fails on real mismatches.
