# Copy, locales and errors

## Catalog rules

- `src/i18n/messages/en.ts` is the source of truth (`MessageKey = keyof typeof en`), and the other five
  catalogs are complete typed records: add a key to `en.ts` and all five with identical placeholders and form
  count, then use `t('key')` / `t('key', { ... })` at the UI boundary.
- No hardcoded CJK in UI string literals (comments are fine); `pnpm i18n:scan` catches code literals, not
  catalog values. Placeholders are named `{name}`, never translated, and may appear in another order; plurals
  use `'singular | plural'` with `tp(key, count)`, one form for `zh-CN`, `zh-TW`, `ja` and `ko`, two for `es`.
- Locale is live: `applyLocale()` updates `<html lang>`, notifies non-React subscribers and pushes a
  `localeEffect` into every editor view, so DOM-producing CodeMirror extensions must subscribe in
  `src/editor/locale.ts` — React rerenders alone will not update them. A setting shared by every window
  belongs in `SHARED_KEYS` in `src/store/settings.ts`.
- A new locale adds `messages/<locale>.ts`, updates `LOCALES` / `LOCALE_LABELS`, and maps the tag in
  `src-tauri/src/i18n.rs` for native Dock/tray copy.

## Backend errors

Rust sends codes, not translated sentences: `AppError::c("code")` for a translatable key,
`AppError::p("code", params)` for a key plus named placeholders, and `AppError::new(raw)` only for external
tool output, rendered through `error.message` and never translated.

The frontend renders `error.<code>` and params must match the catalog placeholders. `src-tauri/src/error.rs`
maps IO kinds to `io.notFound` / `io.permissionDenied` / `io.other`, which the i18n checker parses; every
other `error.<code>` must be a code Rust actually emits, and every emitted code needs all six entries.
