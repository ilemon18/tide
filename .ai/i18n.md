# Copy, locales and errors

## Ownership and catalog changes

- src/i18n/messages/en.ts defines MessageKey. All five other catalogs are complete typed records. Add
  every key to all six, preserve named placeholders, then call t at the UI boundary. Keep actionable errors,
  consequential behavior and accessible labels; use clear actions and contextual tooltips for optional help.
- No hardcoded CJK UI literals (comments allowed). i18n:scan scans code, not catalogs. Named {name}
  placeholders stay untranslated/reorderable. tp uses singular | plural: one form in zh-CN/zh-TW/ja/ko,
  two in es. A locale addition updates messages, LOCALES/LOCALE_LABELS and Rust i18n tags for Dock/tray.

## Live locale and errors

- applyLocale updates html lang, non-React subscribers and CodeMirror localeEffect. DOM extensions must
  subscribe via src/editor/locale.ts and unsubscribe on destroy; React renders alone do not refresh them.
  Cross-window setting changes also follow SHARED_KEYS in [runtime.md](./runtime.md).
- Error transport follows [context.md](./context.md): Rust sends codes/params, frontend resolves error.<code>.
  Placeholder names match params. Raw external-tool error.message is never translated. Rust error.rs maps
  IO kinds to io.notFound/io.permissionDenied/io.other; the checker parses those mappings. Every emitted
  code needs six catalog entries, and every other error key must correspond to an emitted code.

## Change map and verification

Change Rust error emitters/IO mappings, IPC DTOs and all catalogs together. Existing i18n parity checks
protect keys/placeholders/plurals/error coverage; i18n:scan protects CJK literals. Execute only requested
checks via [checks.md](./checks.md).
